CS4.5 生成流程与shellcode简记

发表于 2026-11-15 分类于 免杀对抗

生成类型

ida的java-decompiler.jar反编译CS4.5

CS的生成界面共有四套对应的代码，分别对应：

  • windows stageless
  • windows stager
  • payload stager
  • payload stageless（CS4.7引入）

在GUI呈现如下：

各自作用：

Payload Generator：生成各种类型的 stager shellcode，作用是通过网络拉取Stage并内存运行实现上线

Windows Executable：生成windows下可以直接运行stager shellcode的PE文件，作用是通过网络拉取Stage并内存运行上线

Windows Executable（Stageless）：生成windows下可以直接运行Stage的PE文件，作用是直接上线

Payload Generator

PayloadGeneratorDialog#dialogAction() 通过 ScListener#getPayloadStager() 获取stager

stager的生成最终会通过 GenericHTTPStager#generate()

stager 模板文件有五种

stager是一段shellcode模板，即常见的 fc48

然后会根据listener配置按照固定偏移量、替换占位符来patch stager模板文件，这里我使用默认的C2Profile就会随机生成UA、URI，生成针对特定listener的 stager

最后根据选择生成的类型将stager变形为对应的输出类型

Windows Executable

获取stager步骤同Payload

为了将PE和stager结合，通过 BaseArtifactUtils#patchArtifact() 函数，对 artifact 系列PE进行patch

直接将stager异或加密，然后构造如下结构，替换 artifact pe文件的A占位符，完成生成

Windows Stageless

可简单分为两步：

  • patch stub引导头、C2Profile 配置信息到beacon模板中形成 Stage
  • patch Stage到exe中

patch beacon

ScListener#export() 函数会根据payload选择处理不同的DLL，这里跟进HTTP类型

BeaconPayload#exportBeaconStageHTTP() 除了支持UDRL外还有两个重要函数

  • BeaconPayload#exportBeaconStage()：patch beacon中关于 C2Profile 配置信息
  • MalleablePE#process()：patch beacon中关于 stub shellcode引导头、ReflectiveLoader函数字节等

一、BeaconPayload#exportBeaconStage()

对于 sleeve/ 目录下的文件，都是被加密过的（包括beacon、pivot等核心dll、obj文件），解密需要指定密钥

构建 TLV（Type-Length-Value）结构，将C2Profile的配置填入，包括不限于

  • 通信相关：服务器地址、端口、URI、User-Agent、Host头等
  • 行为控制：Beacon 类型、睡眠时间、抖动比例、终止日期等
  • 后渗透与进程：派生进程的路径、SMB 管道名、进程注入等

将整个TLV配置块与 0x2E（46）进行XOR异或，然后替换占位符

二、MalleablePE#process()

PEParser#load(): 解析PE信息

ReflectiveDLL#getReflectiveLoaderInfo(): 通过导出表找到指定导出函数 ReflectiveLoader 偏移，利用指定特征符 CC 90 .. 再次定位偏移量并计算模板填充长度，返回一个信息对象

此时的 ReflectiveLoader 函数还是一片占位符，且偏移量是 0x16444

MalleablePE#pre_process(): 通过一个PEEditor对象，对模板beacon.x64.dll进行 PE 层面定制化修改，从C2Profile 的 stage 块中读取各项配置，然后将这些配置应用从而改变其静态与内存特征以规避检测

例如 setRWXHint() 通过修改PE头信息中的 Characteristic 的 32768（0x8000，IMAGE_FILE_SYSTEM 标志位）信息，借用合法的标志位向ReflectiveLoader提供某些配置信号

MalleablePE#post_process

BeaconRDLL#process() 主要功能是

  1. 获取stub并patch到DOS头中
  2. 获取真正的ReflectiveLoader函数并patch到导出的偏移处

BeaconLoader#getDOSHeaderPatchX64() 获取一个stub shellcode

BeaconRDLL#getReflectiveLoaderFunction() 获取不同的obj文件内容，里面是不同的方法实现的 ReflectiveLoader的具体函数

最后，将真正的ReflectiveLoader进行填充、将stub patch 到DOS头

至此一个包含可用的ReflectiveLoader函数的BeaconDLL（Stage）制作完成

八、调用目标函数

影子空间（Shadow Space）是 Windows x64 调用约定强制要求调用方在栈上预留的一块 32 字节（4 × 8 字节） 区域，专门给被调用的函数使用。在执行 jmp rax 尾调用目标 API之前，手动在栈上挖出影子空间。因为 shellcode 是手写的汇编，编译器不会自动帮它做这件事，所以必须自己 sub rsp, 0x20 来满足 x64 ABI 的要求

Stage stub shellcode 分析

完整的stub shellcode用于定位内嵌在 BeaconDLL中的ReflectiveLoader函数并调用它，然后调用 DllMain

字节 汇编 解释
4D 5A 41 52 db 'MZAR' 数据非指令。伪装 DOS 头，并作为 lea 的锚点，指向 stub 起始（即 DLL 基址）
55 push rbp 保存调用者栈帧指针
48 89 E5 mov rbp, rsp 建立当前栈帧
48 81 EC 20 00 00 00 sub rsp, 0x20 分配 32 字节影子空间，满足 x64 调用约定
48 8D 1D EA FF FF FF lea rbx, [rip - 0x16] 回退 22 字节到 MZAR 处，rbx = Beacon DLL 基址
48 89 DF mov rdi, rbx rdi = DLL 基址，暂存为 ReflectiveLoader 的参数
48 81 C3 44 64 01 00 add rbx, 0x16444 0x16444 是 ReflectiveLoader 的 RVA，rbx = 其绝对地址
FF D3 call rbx 调用 ReflectiveLoader，返回 DllMain 地址到 rax
41 B8 F0 B5 A2 56 mov r8d, 0x56A2B5F0 DllMain 第 3 参数设为 CS 魔数 0x56A2B5F0
68 04 00 00 00 push 4 压入 DLL_PROCESS_ATTACH
5A pop rdx rdx = 4，作为 DllMain 第 2 参数
48 89 F9 mov rcx, rdi rcx = DLL 基址，作为 DllMain 第 1 参数
FF D0 call rax 调用 DllMain(基址, DLL_PROCESS_ATTACH, 魔数)，启动 Beacon

Stage ReflectiveLoader 分析

挑选一个BeaconLoader.VA.x64.o解密后逆向分析可以看到详细的ReflectiveLoader干了什么，简单总结为

  • 解析自身所需 API（优先 Kernel32 EAT，失败则动态解析）

  • 读取 PE 头，根据 0x8000 位决定是否使用 RWX 内存

  • VirtualAlloc 分配内存，复制头和节区

  • 修复导入表、解密混淆节区、处理重定位、设置内存权限

  • 调用 DllMain(DLL_PROCESS_ATTACH, 魔数) 启动 Beacon
